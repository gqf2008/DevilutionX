## Rust Optimizations

### 1. Type Safety

**C++ (runtime checks)**:
```cpp
if (object._otype == OBJ_L1LDOOR || object._otype == OBJ_L1RDOOR) {
    OperateDoor(object);
}
```

**Rust (compile-time checks)**:
```rust
match object.otype {
    ObjectId::L1DoorL | ObjectId::L1DoorR => {
        operate_door(object, send_network_msg)
    }
    _ => false,
}
```

### 2. Enum Exhaustiveness

All match statements on `ObjectId` and `ShrineType` are checked by compiler for completeness.

### 3. Option<T> Safety

Sparse array implementation uses `Option<Object>` to eliminate null pointer errors:
```rust
pub fn get(&self, index: usize) -> Option<&Object> {
    self.objects.get(index).and_then(|obj| obj.as_ref())
}
```

### 4. Iterator Pattern

Object iteration is safe and efficient:
```rust
for (index, object) in manager.iter() {
```

Helper methods compile to same machine code as direct field access:

### 1. File Corruption Recovery

**Incident**: PowerShell batch replace corrupted objects.rs

**Solution**: Complete file rebuild from scratch

**Lesson**:
- Use `multi_replace_string_in_file` for complex edits
- Avoid PowerShell `-replace` for large files
- Always verify file integrity after bulk operations

**Prevention**: Prefer incremental edits over batch operations

### 2. Enum Naming Conventions

**Issue**: ObjectId enum uses capitalization (BookcaseL not BookCaseL)

**Solution**: Verified correct names in objdat.rs before implementation

**Lesson**: Always check enum variant names in source before pattern matching

**Best Practice**: Use `grep_search` to confirm enum definitions
