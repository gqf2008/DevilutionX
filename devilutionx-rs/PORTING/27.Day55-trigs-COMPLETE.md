### ✅ 1. is_warp_open (Rust) vs IsWarpOpen (C++)

**C++ Implementation** (trigs.cpp:81-109):
```cpp
bool IsWarpOpen(dungeon_type type)
{
    if (gbIsSpawn)
        return false;

    if (gbIsMultiplayer && type != DTYPE_NEST)
        return true;

    const Player &myPlayer = *MyPlayer;

    if (type == DTYPE_CATACOMBS && (myPlayer.pTownWarps & 1) != 0)
        return true;
    if (type == DTYPE_CAVES && (myPlayer.pTownWarps & 2) != 0)
        return true;
    if (type == DTYPE_HELL && (myPlayer.pTownWarps & 4) != 0)
        return true;

    if (gbIsHellfire) {
        if (type == DTYPE_CATACOMBS && myPlayer.getCharacterLevel() >= 10)
            return true;
        if (type == DTYPE_CAVES && myPlayer.getCharacterLevel() >= 15)
            return true;
        if (type == DTYPE_HELL && myPlayer.getCharacterLevel() >= 20)
            return true;
        if (type == DTYPE_NEST && IsAnyOf(Quests[Q_FARMER]._qactive, QUEST_DONE, QUEST_HIVE_DONE))
            return true;
        if (type == DTYPE_CRYPT && Quests[Q_GRAVE]._qactive == QUEST_DONE)
            return true;
    }

    return false;
}
```

**Rust Implementation** (trigs.rs:540-583):
```rust
pub fn is_warp_open(
    dtype: DungeonType,
    is_spawn: bool,
    is_multiplayer: bool,
    is_hellfire: bool,
    player_level: i32,
    town_warps: u8,
    farmer_quest_done: bool,
    grave_quest_done: bool,
) -> bool {
    if is_spawn {
        return false;
    }

    if is_multiplayer && dtype != DungeonType::Nest {
        return true;
    }

    match dtype {
        DungeonType::Catacombs if (town_warps & 1) != 0 => return true,
        DungeonType::Caves if (town_warps & 2) != 0 => return true,
        DungeonType::Hell if (town_warps & 4) != 0 => return true,
        _ => {}
    }

    if is_hellfire {
        match dtype {
            DungeonType::Catacombs if player_level >= 10 => return true,
            DungeonType::Caves if player_level >= 15 => return true,
            DungeonType::Hell if player_level >= 20 => return true,
            DungeonType::Nest if farmer_quest_done => return true,
            DungeonType::Crypt if grave_quest_done => return true,
            _ => {}
        }
    }

    false
}
```

**Differences**:
- ✅ **Pure function**: Rust takes all dependencies as parameters (no globals)
- ✅ **Type safety**: `DungeonType` enum vs raw int
- ✅ **Testability**: Easy to test with different inputs (no need for mock Player/Quest)
- **Alignment**: **100%** (perfect logic match)

### ✅ 3. init_l1_triggers (Rust) vs InitL1Triggers (C++)

**C++ Implementation** (trigs.cpp:149-167):
```cpp
void InitL1Triggers()
{
    numtrigs = 0;
    for (WorldTileCoord j = 0; j < MAXDUNY; j++) {
        for (WorldTileCoord i = 0; i < MAXDUNX; i++) {
            if (dPiece[i][j] == 128) {
                trigs[numtrigs].position = { i, j };
                trigs[numtrigs]._tmsg = WM_DIABPREVLVL;
                numtrigs++;
            }
            if (dPiece[i][j] == 114) {
                trigs[numtrigs].position = { i, j };
                trigs[numtrigs]._tmsg = WM_DIABNEXTLVL;
                numtrigs++;
            }
        }
    }
    trigflag = false;
}
```

**Rust Implementation** (trigs.rs:176-206):
```rust
pub fn init_l1_triggers(&mut self, d_piece: &[[u16; MAXDUNY]; MAXDUNX]) {
    self.numtrigs = 0;

    for j in 0..MAXDUNY {
        for i in 0..MAXDUNX {
            if d_piece[i][j] == 128 {
                self.add_trigger(
                    Point { x: i as i32, y: j as i32 },
                    TriggerMessage::PrevLevel,
                    0,
                );
            }
            if d_piece[i][j] == 114 {
                self.add_trigger(
                    Point { x: i as i32, y: j as i32 },
                    TriggerMessage::NextLevel,
                    0,
                );
            }
        }
    }

    self.trigflag = false;
}
```

**Differences**:
- ✅ **Borrowing**: Pass `d_piece` as reference (no global `dPiece`)
- ✅ **Type safety**: `TriggerMessage` enum vs raw message int
- ✅ **Bounds checking**: `add_trigger()` prevents overflow
- **Alignment**: **100%** (perfect logic match)

## 🎓 Technical Decisions

### 1. Pure Function for IsWarpOpen
**Decision**: `is_warp_open()` takes all dependencies as parameters
**Reason**:
- ✅ Testable (no need for global Player/Quest state)
- ✅ Thread-safe (no global access)
- ✅ Reusable (can be called from anywhere)
- ❌ More verbose (8 parameters vs 1 in C++)

**Mitigation**: Callers can wrap in closure if needed

### 2. Dependency Injection for InitTownTriggers
**Decision**: Pass `is_warp_open` as closure to `init_town_triggers()`
**Reason**:
- ✅ Testable (mock warp state easily)
- ✅ Flexible (caller decides warp logic)
- ✅ No global dependencies

**C++ Equivalent**: Calls `IsWarpOpen()` directly (hard dependency)

### 3. TriggerManager Struct vs Global Arrays
**Decision**: All state in `TriggerManager` struct
**Reason**:
- ✅ Thread-safe (each manager is independent)
- ✅ Testable (multiple managers in parallel tests)
- ✅ Rust idiomatic (ownership/borrowing enforced)
- ❌ C++ uses globals (`trigs[]`, `numtrigs`, `trigflag`)

**Alignment**: Core logic identical, memory model differs

### 4. Enum for TriggerMessage
**Decision**: Use `TriggerMessage` enum instead of raw ints
**Reason**:
- ✅ Type safety (can't pass invalid message)
- ✅ Self-documenting (clear intent)
- ✅ Match exhaustiveness checking

**C++ Equivalent**: Uses `interface_mode` enum (WM_DIABNEXTLVL, etc.)

## 💡 Lessons Learned

### Architectural Insights

1. **Pure Functions vs Globals**:
   - Rust's `is_warp_open()` takes 8 parameters (verbose but testable)
   - C++ accesses 4 globals (`gbIsSpawn`, `MyPlayer`, `Quests`, `gbIsHellfire`)
   - Trade-off: Verbosity for testability

2. **Dependency Injection**:
   - `init_town_triggers(&is_warp_open)` enables test mocking
   - C++ calls `IsWarpOpen()` directly (hard dependency)
   - Benefit: Test can inject fake warp state easily

3. **Encapsulation**:
   - `TriggerManager` struct owns all trigger state
   - C++ uses global `trigs[]`, `numtrigs`, `trigflag`
   - Rust enables multiple managers (e.g., client + server)

### Testing Strategies

1. **Boundary Testing**:
   - Test max trigger limit (7 triggers)
   - Test level requirements (10/15/20 for Hellfire)
   - Test quest conditions (Farmer/Grave)

2. **Mock Closures**:
   - `let is_warp_open = |_| true;` for "all warps open" test
   - `let is_warp_open = |_| false;` for "all warps closed" test
   - Easy to test different warp configurations

3. **Quest Chamber Edge Case**:
   - L2 has special logic: skip tile 266 at quest position
   - Test ensures quest chamber entrance not added as trigger
