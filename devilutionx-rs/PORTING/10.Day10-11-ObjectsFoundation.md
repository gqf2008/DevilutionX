## Rust 特有优化

### 1. 稀疏数组优化
**C++**:
```cpp
Object Objects[MAXOBJECTS];  // 固定大小数组
```

**Rust**:
```rust
objects: Vec<Option<Object>>,  // 稀疏数组
active_count: usize,           // 活跃计数
```

**优势**:
- 内存效率: 只存储存在的对象
- 类型安全: `Option` 显式表达 None 状态
- 迭代便捷: `iter().filter_map()` 自动跳过 None

### 2. 迭代器模式
```rust
pub fn iter(&self) -> impl Iterator<Item = (usize, &Object)> {
    self.objects.iter()
        .enumerate()
        .filter_map(|(i, opt)| opt.as_ref().map(|obj| (i, obj)))
}
```

**优势**:
- 零成本抽象 (zero-cost abstraction)
- 链式调用: `manager.iter().filter().map().collect()`
- 懒计算 (lazy evaluation)

### 3. 枚举类型
```rust
pub enum SelectionRegion {
    None,
    Bottom,
    Middle,
    Top,
}
```

**优势**:
- 类型安全: 编译期检查
- 模式匹配: `match selection_region { ... }`
- 内存效率: 1 byte 替代 C++ int (4 bytes)

## 关键决策记录

### 1. 稀疏数组 vs 固定数组
**选择**: `Vec<Option<Object>>`
**理由**:
- Rust idiom: `Option` 清晰表达 None 状态
- 内存效率: 避免 127 个对象的浪费
- 迭代性能: `filter_map` 零成本跳过 None

**权衡**:
- O(1) 访问保持不变
- 额外 `Option` 包装 (1 byte overhead)

### 2. 动画系统实现
**选择**: `update_animation()` 内部状态管理
**理由**:
- 自包含 (self-contained): 无需外部计数器
- 与 C++ 一致: `_oAnimCnt` 计数逻辑相同

**实现细节**:
```rust
pub fn update_animation(&mut self) {
    self.anim_cnt += 1;
    if self.anim_cnt >= self.anim_delay {
        self.anim_cnt = 0;
        self.anim_frame = (self.anim_frame + 1) % self.anim_len;
    }
}
```

### 3. 测试数据限制
**选择**: 仅使用 `ObjectId::L1Light`
**理由**:
- `ALL_OBJECTS` 未完全实现
- 避免假数据污染测试
- 核心逻辑验证不受影响

**计划**: Day 12-13 填充完整对象数据后扩展测试。
