## 🎨 设计改进

### 1. 枚举类型 (C++ vs Rust)

**C++ (宏定义)**:
```cpp
enum _setlevels : int8_t {
    SL_NONE,
    SL_SKELKING,
    SL_BONECHAMB,
    // ...
};
```

**Rust (枚举 + 方法)**:
```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
#[repr(i8)]
pub enum SetLevel {
    None = 0,
    SkelKing = 1,
    BoneChamber = 2,
    // ...
}

impl SetLevel {
    pub fn is_arena(&self) -> bool {
        matches!(self, SetLevel::ArenaChurch | ...)
    }
}
```

**优势**:
- ✅ 类型安全
- ✅ 自动边界检查
- ✅ 模式匹配
- ✅ 方法扩展

### 2. 位标记 (C++ vs Rust)

**C++ (enum class)**:
```cpp
enum class DungeonFlag : uint8_t {
    Missile = 1 << 0,
    Visible = 1 << 1,
    // ...
};
```

**Rust (bitflags)**:
```rust
bitflags! {
    pub struct DungeonFlag: u8 {
        const MISSILE = 1 << 0;
        const VISIBLE = 1 << 1;
        // ...
    }
}
```

**优势**:
- ✅ 位操作类型安全
- ✅ 组合标记检查
- ✅ 自动实现位运算符
- ✅ Debug 输出友好

### 3. 数据封装 (C++ vs Rust)

**C++ (全局数组)**:
```cpp
extern uint8_t dungeon[DMAXX][DMAXY];
extern DungeonFlag dFlags[MAXDUNX][MAXDUNY];
extern int8_t dPlayer[MAXDUNX][MAXDUNY];
// ... 13 个全局数组
```

**Rust (结构体封装)**:
```rust
pub struct Dungeon {
    pub tiles: [[u8; DMAXY]; DMAXX],
    pub flags: [[DungeonFlag; MAXDUNY]; MAXDUNX],
    pub player_layer: [[i8; MAXDUNY]; MAXDUNX],
    // ... 所有字段在一个结构体中
}
```

**优势**:
- ✅ 封装性更好
- ✅ 避免全局状态
- ✅ 便于测试
- ✅ 生命周期管理
- ✅ 多地牢实例支持

## 🔍 移植细节

### 1. 内存布局对齐

**C++ 数组顺序**:
```cpp
uint8_t dungeon[DMAXX][DMAXY];  // [x][y]
```

**Rust 数组顺序**:
```rust
tiles: [[u8; DMAXY]; DMAXX]  // [x][y]
```

✅ **完全对齐** - 与 C++ 内存布局一致

### 2. 坐标系统

**Tile Space (DMAXX × DMAXY)**:
- 大瓦片坐标系统
- 用于地牢生成算法
- 范围: 0-111

**Piece Space (MAXDUNX × MAXDUNY)**:
- 微瓦片坐标系统
- 用于渲染和碰撞检测
- 范围: 0-111
- 每个 tile = 4 pieces (2×2)

✅ **坐标系统完全对齐**

### 3. 位标记操作

**C++ 操作**:
```cpp
dFlags[x][y] |= DungeonFlag::Lit;
dFlags[x][y] &= ~DungeonFlag::Visible;
bool isLit = HasAnyOf(dFlags[x][y], DungeonFlag::Lit);
```

**Rust 操作**:
```rust
dungeon.add_flags(x, y, DungeonFlag::LIT);
dungeon.remove_flags(x, y, DungeonFlag::VISIBLE);
let is_lit = dungeon.has_flags(x, y, DungeonFlag::LIT);
```

✅ **语义完全一致，接口更安全**

## 💡 关键设计决策

### 1. 全局状态 → 结构体封装

**原因**:
- C++ 使用全局数组便于快速访问
- Rust 推荐封装避免全局状态
- 结构体便于测试和多实例

**实现**:
```rust
pub struct Dungeon {
    // 所有数据在一个结构体中
}

impl Dungeon {
    // 所有操作作为方法
}
```

### 2. 边界检查策略

**C++ 方式**:
- 使用宏 `InDungeonBounds()` 手动检查
- 大部分代码直接数组访问

**Rust 方式**:
- 所有公共方法内置边界检查
- 返回默认值而非 panic
- 开发模式下 panic，发布模式返回默认值

```rust
#[inline]
pub fn get_tile(&self, x: usize, y: usize) -> u8 {
    if x < DMAXX && y < DMAXY {
        self.tiles[x][y]
    } else {
        0  // 安全默认值
    }
}
```

### 3. 类型安全的枚举

**优势**:
- 编译期检查
- 模式匹配确保完整性
- 避免魔术数字

**示例**:
```rust
match dungeon_type {
    DungeonType::Town => { /* ... */ },
    DungeonType::Cathedral => { /* ... */ },
    DungeonType::Catacombs => { /* ... */ },
    // 编译器确保所有分支覆盖
}
```
