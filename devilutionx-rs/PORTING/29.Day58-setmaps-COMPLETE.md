## 📋 任务概述

实现特殊任务地下城(Set Maps)系统,负责加载预设的任务关卡。与程序生成的普通关卡不同,这些是手工设计的地图文件(.dun格式),用于关键任务战斗(如骷髅王、大主教拉撒路等)。

### C++ 系统规模
- **文件大小**: 200 行左右(setmaps.h + cpp)
- **核心功能**:
  - 9 种 Set Level 定义(5个任务关卡 + 3个竞技场 + Maze占位)
  - `LoadSetMap()` 主加载函数(根据setlvlnum调度)
  - 对象初始化函数(AddSKingObjs/AddSChamObjs/AddVileObjs)
  - �技场支持(Hellfire扩展内容)
- **特点**:
  - 每个Set Level有专属加载逻辑
  - 需要文件I/O加载.dun地图
  - 需要对象系统初始化特殊对象
  - 需要触发器系统设置关卡转换

## 🎓 技术要点

### 1. 竞技场系统设计

竞技场是Hellfire扩展内容,用于PvP战斗:
```rust
pub fn is_arena(&self) -> bool {
    matches!(
        self,
        SetLevel::ArenaChurch | SetLevel::ArenaHell | SetLevel::ArenaCircleOfLife
    )
}
```

每个竞技场有专属地图文件和出口触发器:
- Church Arena: church.dun, exit at (28, 20)
- Hell Arena: hell.dun, exit at (33, 26)
- Circle of Life: circle_of_death.dun, exit at (29, 26)

### 2. 地图文件加载模式

不同类型的Set Level使用不同的加载函数:
- **Cathedral/Crypt**: LoadL1Dungeon (骷髅王, 拉撒路)
- **Catacombs**: LoadL2Dungeon (骷髅骨头室)
- **Caves**: LoadL3Dungeon (毒水井)
- **Hell**: LoadL4Dungeon (地狱竞技场)

### 3. Pre-Dungeon 加载机制

部分关卡需要两次加载:
```cpp
LoadPreL1Dungeon("levels/l1data/sklkng1.dun");  // 先加载背景
LoadL1Dungeon("levels/l1data/sklkng2.dun", ...); // 再加载主地图
```

Pre-Dungeon通常是背景图层或外围区域。

### 4. 对象初始化坐标系统

对象使用两种坐标:
- **Position**: 对象在地图上的位置 `(x, y)`
- **Region**: 对象所占区域 `(x, y, width, height)`

示例:
```cpp
ObjectAtPosition({ 64, 34 })           // 对象位置
    .InitializeLoadedObject(
        { { 20, 7 }, { 3, 3 } },       // 区域: (20,7) 大小3x3
        1                              // 对象ID
    );
```
