## 坐标系统对齐计划(基于 C++ 原版权威实现)

研究报告已确认 5 个根因。修复原则:**信任 SDL2 的 `set_logical_size(640,480)` 自动转换鼠标坐标(C++ 就是这么做的),删掉 Rust 多余的手写转换层,消除二义性**。

### 修复 1:统一鼠标坐标转换(菜单错乱主因)
**文件:`src/main.rs`**
- 删除 `window_to_logical` 里的启发式分支(line 59-61 "已在 0..640 内就不转")。这个启发式是 bug 源:当 logical_size 已转换事件坐标到逻辑空间时,它"凑巧"对;但当逻辑坐标恰好落在小范围时会误判。
- **改法 A(推荐,对齐 C++)**:既然 `set_logical_size(640,480)` 已启用,SDL2 保证鼠标事件坐标自动是逻辑坐标。所以 MouseButtonUp/MouseMotion/MouseMotion 直接用原始 x,y,**不再调 window_to_logical**。`mouse_state()` 轮询:SDL2 logical_size 下 mouse_state 也返回逻辑坐标,直接用,不转。
- 即:把 `window_to_logical` 调用全部移除,事件坐标直接用。这完全对齐 C++(events.cpp:408 "No-op in SDL2")。
- 同时移除诊断 println(`[DEBUG] MouseButtonUp`、`[Window] logical_size=...`),它们是临时的。

### 修复 2:游戏循环接入鼠标处理(进游戏没鼠标主因)
**文件:`src/game/game_loop.rs` `handle_event`(~line 406-433)**
- 当前 `_ => {}` 丢弃所有非键盘事件。
- 加 `Event::MouseMotion { x, y }` / `Event::MouseButtonDown/Up` 分支:维护一个 `GameLoopState` 里的 `mouse_pos: (i32, i32)` 字段(逻辑坐标,直接用 x,y)。
- 在 `draw_and_blit` 末尾画一个简单光标标记(彩色十字/方块,类似菜单的 cursor)在 `mouse_pos`,让玩家在游戏里看到鼠标。
- (可选)鼠标左键点击 → 计算 `cursPosition`(屏幕→tile),用于后续点击移动/攻击。第一阶段先只画光标+更新位置,移动仍用键盘。

### 修复 3:玩家屏幕位置扣面板(位置偏移)
**文件:`src/game/game_loop.rs` `draw_and_blit`(~line 742)**
- 当前玩家/相机中心画在 `(LOGICAL_WIDTH/2, LOGICAL_HEIGHT/2)` = (320, 240)。
- C++ 画在 `(screenWidth/2, (screenHeight - panelHeight)/2)`。面板高 128(底部 HUD),所以视口中线 = (480-128)/2 = 176。
- 改:玩家屏幕中心 Y 从 240 改为 176(或 `LOGICAL_HEIGHT/2 - PANEL_HEIGHT/2`,PANEL_HEIGHT=144 当前 HUD 高度,调整为扣面板的中线)。让玩家在画面上半部,不被 HUD 盖住。

### 修复 4:进游戏后恢复 OS 光标或画光标
**文件:`src/main.rs` + `src/game/game_loop.rs`**
- 当前 `set_cursor_visible(false)` 全局隐藏 OS 光标。
- 菜单阶段画自制 cursor(已有 render_cursor)。
- 游戏阶段:方案 A——进游戏时 `window.set_cursor_visible(true)` 恢复 OS 光标(最简单,先能看到鼠标);方案 B——在 draw_and_blit 画自制光标(更接近 C++ 的 hwcursor)。**先用方案 A**(恢复 OS 光标),确保鼠标可见,后续再美化。

### 修复 5(可选):菜单 LOGO/焦点环位置核对
- 研究确认菜单项坐标(list_x=64, list_y=192, w=510, h=43)与 C++ 完全一致。
- LOGO 在 `ui_y + 30`,文字菜单在 `ui_y + 192`。这些和 C++ 对齐。
- 如果修复 1 后菜单位置仍不对,再单独核对 LOGO 高度(smlogo 帧高 154,可能需要垂直居中调整)。

### 不改的
- 不改 `set_logical_size(640,480)` 本身(C++ 也用 logical_size,保留是对的)
- 不改 `options.rs` 默认分辨率(1280×720 窗口 + 640×480 logical 是合理的)
- 暂不改移动模型(C++ 点击寻路 vs Rust 键盘滑动)——先用键盘移动可用,鼠标点击移动作为后续
- 暂不碰 levels/ 渲染细节(地图"有点乱"是 tile 映射问题,先确保坐标/鼠标对)
