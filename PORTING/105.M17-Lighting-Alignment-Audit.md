### ⚠️ Simplified Implementations (Functional but Not 1:1)

#### 1. `DoLighting()` - Light Cone Calculation

**C++ Implementation** (lines 127-189):
- Uses `LightConeInterpolations[8][8][16][16]` lookup table
- Uses `LightFalloffs[16][128]` for radius-based falloff
- Applies 4-quadrant rotation via `RotateRadius()`
- Handles sub-tile offset interpolation

**Rust Implementation** (simplified):
- Uses simple distance-squared calculation
- Linear falloff formula: `(max_dist - dist) * LIGHTS_MAX / max_dist`
- No sub-tile interpolation
- No quadrant rotation

**Impact**: Visual difference in light shape (circular vs. optimized cone)

**Recommendation**:
- ⏳ Add `LightFalloffs` table generation in future pass
- ⏳ Add `LightConeInterpolations` if visual fidelity required

#### 2. `DoUnLight()` - Light Removal

**C++ Implementation** (lines 114-125):
- Restores from `dPreLight` buffer
- radius + 2 to handle diagonal movement artifacts

**Rust Implementation**:
- Sets to `LIGHTS_MAX` (max darkness)
- Does not use pre-light buffer

**Impact**: Minor - reset behavior differs but functional

#### 3. `MakeLightTable()` - Palette Generation

**C++ Implementation** (lines 230-295):
- Generates 16 light tables for palette remapping
- Special handling for Hell (blood wall lighting)
- Special handling for Nest/Crypt (lava brightness)

**Rust Implementation**:
- Stub arrays only
- No palette generation

**Impact**: Rendering will need these tables for correct colors

**Recommendation**:
- ⏳ Implement `make_light_table()` when connecting to renderer

#### 4. `LoadTrns()` - Color Translation Tables

**C++ Implementation** (lines 224-228):
- Loads `infra.trn`, `stone.trn`, `pause.trn` from MPQ

**Rust Implementation**:
- Zero-initialized stub arrays

**Impact**: Infravision, stone curse, pause effects won't work

**Recommendation**:
- ⏳ Implement when asset loading system ready
