```rust
/// Calculate Chebyshev distance to enemy
/// **C++ Reference**: `Monster::distanceToEnemy()` inline
pub fn distance_to_enemy(monster: &Monster) -> u32 {
    let dx = (monster.x - monster.enemy_position.x).abs();
    let dy = (monster.y - monster.enemy_position.y).abs();
    dx.max(dy) as u32
}

/// Random boolean with 1/frequency chance
/// **C++ Reference**: `FlipCoin(frequency)` utils.cpp
pub fn flip_coin(frequency: u32) -> bool {
    if frequency == 0 { return false; }
    rand::random::<u32>() % frequency == 0
}
```

## 🎓 Key Learnings

### 1. Goal-Based State Machines
Monster AI uses **MonsterGoal** enum for high-level behavior:
```rust
pub enum MonsterGoal {
    Normal = 0,      // Default behavior
    Retreat = 1,     // Fleeing/defensive
    Healing = 2,     // Seeking health
    Move = 3,        // Pathfinding
    Attack = 4,      // Aggressive pursuit
    Inquiring = 5,   // Investigation
    Talking = 6,     // NPC dialogue
}
```

**Pattern**: AI functions check `monster.goal` to determine behavior phase
- Example: Sneak uses Retreat for fade-out, Normal for fade-in
- Example: Counselor uses Retreat for teleport countdown

### 2. Goal Variables as State Memory
```rust
monster.goal_var1: i16  // Primary counter/state
monster.goal_var2: i16  // Secondary state (turn direction, cooldown)
```

**Usage Patterns**:
- **Rhino**: var1 = step counter, var2 = turn direction
- **Counselor**: var1 = teleport countdown
- **HorkDemon**: var1 = spawn count (0-10), var2 = spawn cooldown

### 3. Borrow Checker Solutions for State Updates
**Problem**: Can't borrow monster mutably twice
```rust
round_walk(monster, md, &mut monster.goal_var2)  // ❌
```

**Solution**: Extract → Modify → Write Back
```rust
let mut turn_dir = monster.goal_var2;
round_walk(monster, md, &mut turn_dir);
monster.goal_var2 = turn_dir;  // ✅
```

### 4. Direction System Idioms
**C++ Pattern**:
```cpp
Direction md = GetDirection(monster.position.tile, monster.enemyPosition);
dir = Right(md);   // Rotate right
dir = Left(md);    // Rotate left
```

**Rust Pattern**:
```rust
let md = get_monster_direction(monster);
let dir = md.right();  // Method call
let dir = md.left();   // Method call
```

### 5. Test-Driven Development for AI
**Pattern**: Test state transitions, not randomness
```rust
#[test]
fn test_ai_sneak_retreat_on_hit() {
    monster.var1 = MonsterMode::HitRecovery as i16;
    ai_sneak(&mut monster);
    assert_eq!(monster.goal, MonsterGoal::Retreat);  // State change
}
```

**Avoid**:
```rust
// ❌ Don't test random outcomes
assert_eq!(monster.mode, MonsterMode::MeleeAttack);  // Might fail

// ✅ Test possible outcomes
assert!(
    monster.mode == MonsterMode::MeleeAttack ||
    monster.mode == MonsterMode::Walk
);
```
